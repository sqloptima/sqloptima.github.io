You restore a SQL Server 2016 database onto SQL Server 2022. The application is fine at compatibility level **130**. You flip to **160** and latency spikes.

That pattern is usually **Cardinality Estimator and optimizer plan change**, not a broken migration. Compatibility 160 turns on a newer CE, different transformations, and Intelligent Query Processing features that can reshape joins, grants, and parallelism for the same T-SQL.

## Do this first

1. Leave production at **130** until Query Store holds a golden plan set
2. Capture 3–7 days of plans under real load
3. Reproduce at **160** in UAT with the same workload
4. Force last-good plans or apply scoped CE bridges for top regressions
5. Refresh statistics (FULLSCAN on hot tables) and align MAXDOP / CTFP / TempDB
6. Cut over only after rollback to 130 is rehearsed

```sql
-- Emergency rollback
ALTER DATABASE [YourDB] SET COMPATIBILITY_LEVEL = 130;
```
