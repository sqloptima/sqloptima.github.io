Rewrite the monster into named CTE stages for humans, then materialize expensive stages into
`#temp` tables when the optimizer keeps underestimating. Index the temp when the next step
filters or joins on it more than once.

Do not assume every CTE is materialized — in SQL Server it usually is not. Measure with actual
plans, not folklore.

## Why intermediate result design deserves a method

The central principle is that CTEs improve expression but do not automatically materialize or create statistics. A single metric, recommendation, or successful command is not enough. The decision has to connect an observed symptom to a plausible cause, a controlled change, and a result that can be verified under the workload that matters.

## Evidence to collect

Use evidence from the same time window whenever possible:

- estimated versus actual rows
- repeated references to the intermediate result
- tempdb cost and indexing opportunity
- compile behavior and parameter skew

## A practical workflow

1. Start with the simplest correct query.
2. Inspect the actual plan and estimates.
3. Test a temporary-table breakpoint when estimates diverge.
4. Compare reads, CPU, duration, and concurrency.

## Common mistakes

Avoid these shortcuts:

- assuming every CTE is materialized
- replacing all CTEs with temp tables
- testing only one parameter value

## Verification and completion

Define completion before making the change. Confirm correctness first, then compare latency, throughput, reads, CPU, waits, storage behavior, or recovery time as appropriate for **Breaking complex logic with CTEs and temp tables**. Test negative and boundary cases, not only the path expected to succeed. Watch the system long enough to cover the relevant workload pattern.

### What it does

Reports TempDB files, size, growth, placement, and configuration signals relevant when temporary objects or spills become part of a rewrite. The script is diagnostic and does not apply an automatic remediation. Result values still need workload context, a second supporting signal, and a before-and-after comparison.
